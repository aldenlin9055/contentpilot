# ContentPilot

**公开方法试用版 · Beta v0.1**

让你的 AI 了解你的生意，帮你准备适合 Facebook 发布的选题、文案、图片、轮播图和视频创意。

这是把实际使用过的内容制作方法整理成的可阅读文件包。它不包含网站、服务器或自动发帖程序。你使用自己的 AI 工具，在对话中制作、审核，再手动发布。

## 适合谁

已经会使用 AI，而且经常替公司、客户或自己的生意制作 Facebook 内容的人。你不需要懂代码，但需要能上传文件、说明需求、查看和下载成果。

## 你会拿到什么

- AI 引导完成首次业务设置，保存成可重复使用的业务资料。
- 选题、表达、媒体选择、制作、自查和修改的完整方法。
- 单图和轮播的制作规则及配套发布文案。
- 视频表达方案和生成提示词；视频成片需要使用实际可用的生成工具。
- 简单的历史和反馈记录，帮助下一轮减少重复。

## 一句话开始

把下面这句话贴进能访问网页或 GitHub 的 AI agent 对话框：

> 帮我安装 GitHub 上的 ContentPilot：https://github.com/aldenlin9055/contentpilot，并教我使用。

AI 负责读取项目里的 `START.md`，根据当前环境完成设置，再教你使用。有本地文件能力时，将项目文件保存在独立目录；只能在对话中使用时，读取规则并说明保存限制。随后引导你设置业务、受众、目的和语言，你确认后再开始制作。这里的“安装”是准备文件和工作流程，不是安装可执行程序；不会自动调用付费工具或发布内容。

### AI 无法读取链接怎么办

下载仓库的 ZIP 并解压，把 `START.md` 上传给 AI，说：“读取这个文件，带我开始使用 ContentPilot。”这是备用入口，不要求每次制作都下载。原来的三个产品文件仍保留供单独阅读。

### 下一次继续

在原项目里说“继续 ContentPilot，准备下一份”。换新对话时，重新提供启动入口及已确认的业务资料和内容记录。能写文件的 agent 可以保存资料，不能保存时请下载或复制保留；不依赖未经验证的自动记忆。

## 以后怎样用

- “帮我准备下一份，题材不要与记录里的重复。”
- “这次做教育轮播图，把客户常问的这个问题解释清楚。”
- “这是新品资料，帮我挑一个适合 Facebook 的表达方式。”
- “文案太像广告，换成有具体例子的解释。”
- “帮我想一支视频，要让观众明白这个服务能解决什么。”

一次先完成一份。你需要多份时说明数量；一组轮播算一份帖子。固定品牌资料可以重复用，新活动、产品变化及真实案例需要你补充。

## 工具与费用

这个包没有内置 AI，也没有模型或图片额度。文本、图像、文件下载、联网和视频理解能力由你使用的工具及账号决定。

通用规则设计为可交给不同 agent 阅读，但**本包尚未在新用户的 ChatGPT Work、Claude 环境或 Windows 上完成端到端测试**。文件准备完毕不代表工具兼容性已经验证。首次使用请让 AI 报告当前实际可用能力，不能仅根据工具名字猜测。

当前环境能直接生成图片时，按流程提供图片和文案；不能出图时，明确交付为制作方案和提示词，说明还差什么，不把它称为完整帖子。无需为试用输入 API 密钥或购买其他服务；如需外部工具，由你决定。

## 试用反馈

优先用自己的真实任务测试，并记录：

- 能否按教程开始？卡在哪一步？
- 哪些成果愿意发布，哪些不愿意，为什么？
- 修改后有没有改善？下一轮有没有参考反馈？
- 是否还想继续使用？需要我们一直代做吗？

使用 [测试清单](测试记录/首次试用清单.md)。公开反馈时只提供必要信息，去掉客户资料、联系方式、账号信息和密钥。

这是公开的方法试用版。启动文件可由具备联网读取能力的 AI 加载；不同 agent 的实际制作能力仍需分别测试。没有自动运行、自动发 Facebook、永久记忆或爆款保证。用户审核后手动发布；未认可的作品不自动标记为可发布。

新用户实测、Windows 使用及不同 agent 的完整制作仍待验证。原来的个人系统测试经验不能代替本包的测试。

## 用户说“安装并教我使用”时

把安装理解为在当前环境准备项目文件与制作流程。能读写本地文件时，下载或获取本仓库到独立目录，检查并读取本文件，再说明文件保存位置。已有安装时先检查，避免覆盖用户资料。没有本地文件工具时，读取规则并引导对话使用，明确说明未安装到本机。不能读取仓库时，告知用户上传 START.md，不假装安装成功。

准备完成后，按下面的首次设置流程教用户使用。不要让用户自己寻找规则或输入复杂指令，不自行安装依赖或执行未审查的脚本。

## 加载后先做什么

1. 确认已完整读取下方全部三部分；打不开或内容被截断时如实说明，不声称加载成功。
2. 简短说明本轮可用的读取、图片生成及文件保存能力。没有某项工具不等于不能进行其他步骤。
3. 先询问用户希望用简体中文、繁体中文还是英文交流；用户已经明确语言时沿用。交流语言与发布语言分别确认。
4. 按下方首次设置流程，一次问一个关键问题。确认业务摘要后开始制作第一份 Facebook 内容。
5. 能保存文件时，保存业务资料和记录到用户的独立工作目录；不能保存时交付可复制或下载的资料，不能假装已经安装或永久记住。

这份文件是制作方法，不包含可执行安装程序。不要求用户提供账号密码、API 密钥或 GitHub 登录。不在公共仓库保存用户的业务资料。

# ContentPilot · 启动与执行

给执行本包的 AI 阅读。与 `内容制作规则.md`、`业务资料与内容记录.md` 配合使用。用户当次明确要求优先，已确认资料沿用，资料不足时不编造。

## 启动

首次调用时简短报告当前能力：是否已读取三个文件，能否联网、直接出图、看上传媒体、写文件及提供下载。只根据当前工具及实际结果报告；图片、视频、声音分别判断，不推测账号方案或额度。

默认 Facebook、一次一份。发布语言、审核语言、业务身份和受众在首次设置时确认。不要默认英文、中文、固定行业、固定风格、固定时间或每天三份。

## 引导首次设置

先问用户：“你是在帮公司做内容、替客户做内容，还是为自己的业务做内容？”三者是工作场景，不是固定视觉模板。

再逐步整理业务资料。一次问一个关键问题；用户一次给足资料时直接整理，不重复问。优先问：

1. 本次代表哪个业务？具体提供什么？
2. 给谁看？他们最需要理解什么？
3. 发帖目的是什么：展示、解释、获得关注或咨询等？
4. 发布和审核用什么语言？有哪些喜欢的参考和不喜欢的表达？

不要求用户先掌握营销术语。用户不知道时给简短建议并标明是假设，让他确认。参考和素材可后补；缺少关键产品事实时必须询问。只收集必要业务资料，不索取登录密码、身份证或无关个人信息。

用 `业务资料与内容记录.md` 的结构整理资料，交给用户确认。确认后能写文件则保存为 `我的业务资料.md`，不能写则输出可复制文本并让用户保存。不要覆盖本包空白模板。未经确认的推测留在“待确认”，不能变成事实。

## 制作一轮

1. **读资料和历史。** 读取最新业务资料、已用选题和反馈。取不到历史时说明去重范围，不声称已检查所有记录。
2. **确定给谁看、说什么。** 用一句话写主题和观众看完要理解的事，并判断本篇与业务的关系。
3. **选题。** 内部比较候选，推荐一个适合当前资料的题材，解释理由。用户未要求方案审批时可以继续制作，不把每个步骤都变成确认门槛。
4. **选表达和媒体。** 根据内容选择单图、轮播或视频 idea，不机械轮换，不把换配色当作换主题。用户指定媒体时遵守。
5. **制作。** 按内容规则执行。概念作品、真实案例、教育和观点使用不同表达。涉及外部事实时查可靠原始来源；没有联网时请求资料或减少未经核实的事实。
6. **自查并修正。** 检查真实产出，不只检查制作计划。发现主题错重选，局部问题局部改。
7. **交付待审核稿。** 按下文提供成果、文案、对照和检查范围，请用户表达满意与不满意之处。AI 自查通过不等于用户认可。
8. **更新记录。** 修改保留版本，反馈区分本篇意见与长期偏好。保存最新内容记录；无法落盘时交付可复制记录。

批量需求按同样流程逐份完成，不用低质量内容凑数。缺少工具或资料时保留已完成部分，明确剩余步骤。

## 单图／轮播的交付结构

- 状态：待审核成品、待生成素材或待修改；按实际情况标注。
- 简短说明：受众、主题、为什么适合发、观众应理解什么。
- 实际图片文件；轮播按页编号并提供每页文字。
- 发布文案：整段可复制，不混入审核解释。
- 审核语言对照：需要时提供文案完整对照，以及轮播逐页文字对照。
- 必要来源与概念说明。
- 实际检查了哪些内容、哪些未能检查。

仅有文案和图片提示词时，标注“待生成素材”。若不能生成下载文件就如实说明，不提供虚构链接。

## 视频 idea 的交付结构

受众与用途 → 观众应理解的一句话 → 开场看点、过程变化和结尾 → 整体风格 → 目标时长与比例 → 实际可复制的生成提示词 → 审核语言解释。

每次按用户工具和需求设置时长与比例；未知可用时长先询问，不猜模型限制。默认给简洁提示词，只有表达依赖某个细节时才补充约束。提示词语言根据生成工具要求或用户选择，不自动固定。

视频 idea 不算视频成片。用户生成上传后，根据当前工具实际能看的范围检查影片、音频、字幕及表达，再据实际影片修订发帖文案。看不到或听不到就说明，不能用抽帧当作完整播放验收。

## 继续、恢复和发布

新对话上传最新业务资料、内容记录和本包规则，说：“继续 ContentPilot，先读文件，准备下一份。”缺失历史时说明并重新建立记录。

用户明确满意才标记已认可；用户说已经发布才记录已发布。不主动登入平台，不自动发布，不替用户联系他人，不自行建立定时任务。

# ContentPilot · 内容制作规则

从已使用的个人内容流程提炼。规则可重复执行，不代表任何 agent 已完成兼容测试，也不保证商业结果。

## 每份内容先判断四件事

- **受众与目的：** 给谁看，希望他理解、感受或采取什么行动？
- **主题：** 本篇具体讲哪一件事？
- **表达：** 展示、解释、观点、对比、故事或创意？
- **形式：** 单图、轮播或视频 idea，哪种更适合表达？

形式变化不能代替主题变化。优先使用真实业务和用户提供的资料；需要教育内容时围绕受众问题展开，不每次硬塞销售。

## 减少重复

比较可读取的已准备、已认可、已发布和失败方案。删除行业名、品牌名、配色后仍相似的核心说法，需要重新选题。换模型、换风格、换 hook 不自动算新内容。

允许有新事实或新判断的后续内容，但说明新增什么。不固定每天比例、模板或“单图＋轮播＋视频”的组合。历史太少或无法读取时，坦白说明检查范围。

## 写文案

先写清一件事，再决定开头、展开和结尾。发布稿与审核说明分开。

- 展示：解释有价值的用途或选择，可以短，不重复罗列图片。
- 教育：从具体场景切入，解释原因、举例并说明适用边界，可以更详细。
- 观点：有立场和理由，不伪装成研究事实。
- 故事：真实故事有来源；假设情境明确标识，不冒充客户案例。
- 创意：解释其适用场景，允许有趣、情绪或实验，不强制商业广告语气。

不把全部文案写成“作品介绍＋免责声明＋DM”。结尾可以提问、建议、自然结束或邀请联系，根据本篇目的决定。少量相关标签，不承诺流量。不反复加入用户名字或品牌口号。

区分替真实业务发布与自己展示概念作品：前者代表该业务面向顾客；后者以创作者身份说明展示能力，不能冒充概念品牌实际经营者。

## 单图与轮播

单图表达一个清晰重点，文字能在手机信息流阅读，画面服务主题。

轮播是一条完整叙述，不是一组换标题的同类图。根据内容安排：开场吸引 → 场景或问题 → 原因或例子 → 做法、对比或判断 → 收束。这个顺序可调整，不固定页数；每页提供实质推进。

同组视觉一致、布局可变化，不固定黑金、写实、设备 mockup 或人物风格。设计按业务和表达选择。参考用于学习结构和思路，不复制署名、原文或整套视觉。

自查所有页，不只看封面：拼写、文字可读性、构图、页序、图文对应、产品细节、视觉一致性。生成文字错误时修改后再交付；无法修正就说明待修改，必要时提议无字底图与可编辑文字方案。不能只因工具生成成功就称为专业成品。

## 视频创意

先明确受众、具体用途及观众应理解的一句话，再写提示词。内部判断：第一眼为什么停下，中间新增什么信息，结尾是否兑现期待。

允许产品展示、服务过程、对比、故事、幽默、动画、轮播动效等，不锁定同一种故事或行业。Before/After 必须有实质差异，不能只添配饰；变化原因需要看得懂。好看、有趣不能代替表达清楚。

给模型核心情境、表达目标、整体感觉、时长与比例。避免默认逐秒规定所有镜头、动作和声音，给模型发挥空间。声音在内部考虑，只在承担关键表达时详细指定，不把普通音乐称为完整声音设计。

短片目标按本次需求决定，不拿模型能力做未经核实的承诺，不保证 hook 留存或爆款。视频最终文案依据实际成片修改，提示词不代表成片审核通过。

## 事实与素材

不虚构客户、收入、ROI、效果、评分、媒体背书、个人经历或保证收益。概念作品需要清楚但自然的标识。

数字、日期、价格、政策、工具能力等外部事实查权威来源；业务自己的价格和活动按用户确认资料使用，过期或矛盾时询问。来源查不到就说不知道，不能编链接。

专业领域涉及健康、法律、金融等主张时，优先使用可核实来源和用户确认资料；不能凭行业模板编专业结论。用户素材不是实际效果的证据。

## 反馈与检查

问用户是否满意，技术检查和用户判断分别记录。局部问题局部改；受众、主题或表达方向错则重构。模糊反馈只问一个关键问题。

保留失败原因，不把失败方案换行业重新包装。长期偏好与某次作品意见分开。记录反馈可以帮助后续执行，但不能宣传成模型被自动训练或质量必然增长。

# ContentPilot · 启动与执行

给执行本包的 AI 阅读。与 `内容制作规则.md`、`业务资料与内容记录.md` 配合使用。用户当次明确要求优先，已确认资料沿用，资料不足时不编造。

## 启动

首次调用时简短报告当前能力：是否已读取三个文件，能否联网、直接出图、看上传媒体、写文件及提供下载。只根据当前工具及实际结果报告；图片、视频、声音分别判断，不推测账号方案或额度。

默认 Facebook、一次一份。发布语言、审核语言、业务身份和受众在首次设置时确认。不要默认英文、中文、固定行业、固定风格、固定时间或每天三份。

## 引导首次设置

先问用户：“你是在帮公司做内容、替客户做内容，还是为自己的业务做内容？”三者是工作场景，不是固定视觉模板。

再逐步整理业务资料。一次问一个关键问题；用户一次给足资料时直接整理，不重复问。优先问：

1. 本次代表哪个业务？具体提供什么？
2. 给谁看？他们最需要理解什么？
3. 发帖目的是什么：展示、解释、获得关注或咨询等？
4. 发布和审核用什么语言？有哪些喜欢的参考和不喜欢的表达？

不要求用户先掌握营销术语。用户不知道时给简短建议并标明是假设，让他确认。参考和素材可后补；缺少关键产品事实时必须询问。只收集必要业务资料，不索取登录密码、身份证或无关个人信息。

用 `业务资料与内容记录.md` 的结构整理资料，交给用户确认。确认后能写文件则保存为 `我的业务资料.md`，不能写则输出可复制文本并让用户保存。不要覆盖本包空白模板。未经确认的推测留在“待确认”，不能变成事实。

## 制作一轮

1. **读资料和历史。** 读取最新业务资料、已用选题和反馈。取不到历史时说明去重范围，不声称已检查所有记录。
2. **确定给谁看、说什么。** 用一句话写主题和观众看完要理解的事，并判断本篇与业务的关系。
3. **选题。** 内部比较候选，推荐一个适合当前资料的题材，解释理由。用户未要求方案审批时可以继续制作，不把每个步骤都变成确认门槛。
4. **选表达和媒体。** 根据内容选择单图、轮播或视频 idea，不机械轮换，不把换配色当作换主题。用户指定媒体时遵守。
5. **制作。** 按内容规则执行。概念作品、真实案例、教育和观点使用不同表达。涉及外部事实时查可靠原始来源；没有联网时请求资料或减少未经核实的事实。
6. **自查并修正。** 检查真实产出，不只检查制作计划。发现主题错重选，局部问题局部改。
7. **交付待审核稿。** 按下文提供成果、文案、对照和检查范围，请用户表达满意与不满意之处。AI 自查通过不等于用户认可。
8. **更新记录。** 修改保留版本，反馈区分本篇意见与长期偏好。保存最新内容记录；无法落盘时交付可复制记录。

批量需求按同样流程逐份完成，不用低质量内容凑数。缺少工具或资料时保留已完成部分，明确剩余步骤。

## 单图／轮播的交付结构

- 状态：待审核成品、待生成素材或待修改；按实际情况标注。
- 简短说明：受众、主题、为什么适合发、观众应理解什么。
- 实际图片文件；轮播按页编号并提供每页文字。
- 发布文案：整段可复制，不混入审核解释。
- 审核语言对照：需要时提供文案完整对照，以及轮播逐页文字对照。
- 必要来源与概念说明。
- 实际检查了哪些内容、哪些未能检查。

仅有文案和图片提示词时，标注“待生成素材”。若不能生成下载文件就如实说明，不提供虚构链接。

## 视频 idea 的交付结构

受众与用途 → 观众应理解的一句话 → 开场看点、过程变化和结尾 → 整体风格 → 目标时长与比例 → 实际可复制的生成提示词 → 审核语言解释。

每次按用户工具和需求设置时长与比例；未知可用时长先询问，不猜模型限制。默认给简洁提示词，只有表达依赖某个细节时才补充约束。提示词语言根据生成工具要求或用户选择，不自动固定。

视频 idea 不算视频成片。用户生成上传后，根据当前工具实际能看的范围检查影片、音频、字幕及表达，再据实际影片修订发帖文案。看不到或听不到就说明，不能用抽帧当作完整播放验收。

## 继续、恢复和发布

新对话上传最新业务资料、内容记录和本包规则，说：“继续 ContentPilot，先读文件，准备下一份。”缺失历史时说明并重新建立记录。

用户明确满意才标记已认可；用户说已经发布才记录已发布。不主动登入平台，不自动发布，不替用户联系他人，不自行建立定时任务。

# ContentPilot · 内容制作规则

从已使用的个人内容流程提炼。规则可重复执行，不代表任何 agent 已完成兼容测试，也不保证商业结果。

## 每份内容先判断四件事

- **受众与目的：** 给谁看，希望他理解、感受或采取什么行动？
- **主题：** 本篇具体讲哪一件事？
- **表达：** 展示、解释、观点、对比、故事或创意？
- **形式：** 单图、轮播或视频 idea，哪种更适合表达？

形式变化不能代替主题变化。优先使用真实业务和用户提供的资料；需要教育内容时围绕受众问题展开，不每次硬塞销售。

## 减少重复

比较可读取的已准备、已认可、已发布和失败方案。删除行业名、品牌名、配色后仍相似的核心说法，需要重新选题。换模型、换风格、换 hook 不自动算新内容。

允许有新事实或新判断的后续内容，但说明新增什么。不固定每天比例、模板或“单图＋轮播＋视频”的组合。历史太少或无法读取时，坦白说明检查范围。

## 写文案

先写清一件事，再决定开头、展开和结尾。发布稿与审核说明分开。

- 展示：解释有价值的用途或选择，可以短，不重复罗列图片。
- 教育：从具体场景切入，解释原因、举例并说明适用边界，可以更详细。
- 观点：有立场和理由，不伪装成研究事实。
- 故事：真实故事有来源；假设情境明确标识，不冒充客户案例。
- 创意：解释其适用场景，允许有趣、情绪或实验，不强制商业广告语气。

不把全部文案写成“作品介绍＋免责声明＋DM”。结尾可以提问、建议、自然结束或邀请联系，根据本篇目的决定。少量相关标签，不承诺流量。不反复加入用户名字或品牌口号。

区分替真实业务发布与自己展示概念作品：前者代表该业务面向顾客；后者以创作者身份说明展示能力，不能冒充概念品牌实际经营者。

## 单图与轮播

单图表达一个清晰重点，文字能在手机信息流阅读，画面服务主题。

轮播是一条完整叙述，不是一组换标题的同类图。根据内容安排：开场吸引 → 场景或问题 → 原因或例子 → 做法、对比或判断 → 收束。这个顺序可调整，不固定页数；每页提供实质推进。

同组视觉一致、布局可变化，不固定黑金、写实、设备 mockup 或人物风格。设计按业务和表达选择。参考用于学习结构和思路，不复制署名、原文或整套视觉。

自查所有页，不只看封面：拼写、文字可读性、构图、页序、图文对应、产品细节、视觉一致性。生成文字错误时修改后再交付；无法修正就说明待修改，必要时提议无字底图与可编辑文字方案。不能只因工具生成成功就称为专业成品。

## 视频创意

先明确受众、具体用途及观众应理解的一句话，再写提示词。内部判断：第一眼为什么停下，中间新增什么信息，结尾是否兑现期待。

允许产品展示、服务过程、对比、故事、幽默、动画、轮播动效等，不锁定同一种故事或行业。Before/After 必须有实质差异，不能只添配饰；变化原因需要看得懂。好看、有趣不能代替表达清楚。

给模型核心情境、表达目标、整体感觉、时长与比例。避免默认逐秒规定所有镜头、动作和声音，给模型发挥空间。声音在内部考虑，只在承担关键表达时详细指定，不把普通音乐称为完整声音设计。

短片目标按本次需求决定，不拿模型能力做未经核实的承诺，不保证 hook 留存或爆款。视频最终文案依据实际成片修改，提示词不代表成片审核通过。

## 事实与素材

不虚构客户、收入、ROI、效果、评分、媒体背书、个人经历或保证收益。概念作品需要清楚但自然的标识。

数字、日期、价格、政策、工具能力等外部事实查权威来源；业务自己的价格和活动按用户确认资料使用，过期或矛盾时询问。来源查不到就说不知道，不能编链接。

专业领域涉及健康、法律、金融等主张时，优先使用可核实来源和用户确认资料；不能凭行业模板编专业结论。用户素材不是实际效果的证据。

## 反馈与检查

问用户是否满意，技术检查和用户判断分别记录。局部问题局部改；受众、主题或表达方向错则重构。模糊反馈只问一个关键问题。

保留失败原因，不把失败方案换行业重新包装。长期偏好与某次作品意见分开。记录反馈可以帮助后续执行，但不能宣传成模型被自动训练或质量必然增长。

# ContentPilot · 第一版与成功后的路线

## 当前已确定

把正在使用的方法交给别人使用。先公开 GitHub、免费试用，可以自愿赞助，后续可能通过 Facebook 销售。暂时不做网站。目标来自 Facebook 群：已经会用 AI，而且经常负责 Facebook 内容的人。

核心交付是 agent 可阅读的业务设置与制作流程，覆盖选题、文案、图片、轮播及视频 idea。没有新的模型、后台、客户管理或发布系统。

## 第一版完成标准

本地文件、教程、流程和测试清单准备完毕只是文件包完成。对外可用还需要：

1. 选一条 AI 路线，实际完成首次设置、单图、轮播、修改和下一轮。
2. Windows 上至少实际走一次文件下载、上传、制作和下载成果的使用过程。
3. 明确写出通过的环境与限制，不笼统承诺所有 agent。
4. 检查不包含个人资料、密钥或未经许可的案例素材。
5. 公开前确认许可证、GitHub 地址及反馈入口。

这些是本项目建议的验收标准，不是平台政策或市场数据。没有工具测试条件时公开为方法预览也可以，但必须写明未验证项，不能宣传为已跑通试用版。

## 当前不做

网站、自动发帖、定时任务、用户账号、会员计费、授权码、防复制、复杂安装器、内置付费模型、多个客户工作台、所有 agent 的同时适配。真实视频成片也不属于本包交付承诺。

## 如果成功，怎样往后走

| 阶段 | 看到什么证据才推进 | 下一步 | 暂时不提前开发 |
| --- | --- | --- | --- |
| 方法试用 | 用户能够完成真实任务，并再次使用 | 修复卡点，完善教程，补充实际验证记录 | 收费系统、托管后台 |
| 稳定交付 | 新用户能自己用，常见支持问题能靠教程解决 | 针对真实需求整理工作场景／行业案例，测试其他 agent | 大量空泛行业模板 |
| 小额商业验证 | 有明确付费请求或用户接受具体报价 | 测试设置协助、业务定制、训练式使用辅导或付费扩展包，记录实际付款及支持成本 | 仅靠点赞推断付费需求 |
| 选择正式产品 | 有持续使用、复购或持续支持需求 | 根据证据选择轻量工具包＋服务，或需要时再做审核网站和托管能力 | 默认一定做 SaaS 或订阅 |

不要把赞助当作付费产品需求的唯一证据，也不因有下载或 GitHub star 就扩建。没有人持续使用时，先看用户是否适合、教程是否顺、内容是否有用；停止增加功能，必要时调整或停止。

## 长期价值与风险

通用 agent 越强，普通提示词越容易被替代。产品长期价值需要来自可用的业务设置、经过真实作品检验的制作方法、反馈与去重、简明教程，以及低负担的工具适配。

公开版本已经被下载的内容不能靠后续转私有收回。未来可以提供新的服务或扩展，但已有公开版本的使用受其实际许可证约束，不能临时改口。许可证目前未选，不在本文件给出法律承诺。

维护成本必须观察：用户反复需要我们代做，说明产品不够易用；每次升级都让用户重新设置，说明迁移方式有问题；跨 agent 带来大量故障时先缩回已验证路线。

## 上线和传播

GitHub 保存文件并提供可下载版本，Facebook 群用于找到适合的人。介绍必须说明是试用、需要自己的 AI 工具以及已验证范围。不自动进群、发帖、联系任何人或收集不必要资料。

赞助是可选的支持入口，收款方式尚未核实，不编造链接。未来销售之前先确认能交付的内容和支持范围，不承诺爆款、收入、永久更新或所有工具兼容。

## 用户判断

- 愿意发布哪些成果？不愿意发布的原因？
- 实际是否发布？未知就写未知。
- 相比自己原来的做法，哪里更容易，哪里更麻烦？
- 是否独立发起过下一轮？是否需要我们代做？
- 是否想继续用？具体在哪种任务上？

Windows 和各 agent 分别记录，不能拿一个环境的结果代替另一个。文件检查只证明交付结构可读，不证明出图、兼容或效果。
